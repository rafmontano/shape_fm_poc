# Archived M4 point forecasts

## Scope

ShapeFM distinguishes forecasts generated by its Gate 4 models from official
M4 competition forecasts imported from `M4comp2018`. The archived records are
not models fitted by ShapeFM. They retain the competition's point-forecast
semantics and have `forecast_capability = "mean_only"`.

The only approved mappings are:

| Forecast ID | M4 submission ID | OWA rank | Author |
|---|---:|---:|---|
| `m4_smyl` | 118 | 1 | Smyl |
| `m4_fforma` | 245 | 2 | Montero-Manso, et al. |

The row 7 configuration enables `m4_smyl`. The FFORMA mapping is implemented
and tested but is not automatically enabled for this experiment.

## Gate responsibilities

Gate 1 imports the selected GIFT-Eval series first. Its bounded R adapter loads
`M4` and `submission_info` once, resolves submission IDs through the metadata,
and validates each selected zero-based Daily position (`"0"` → `D1`, `"99"`
→ `D100`). It compares both historical and future identity segments using a
strict float32-aware tolerance, and checks Daily frequency and the official
horizon. Future observations are used only for cross-source identity validation
and are never returned or stored in a reference forecast.

Only the selected series and enabled approved providers are returned. Python's
Gate 1 coordinator validates the identities and lengths again, then remains the
sole DuckDB writer. Identical restarts skip existing rows; any conflicting row
aborts the transaction. Package version, immutable package-source revision, and
a content hash are retained as provenance.

Gate 4's `04_03_forecast_m4_submission.py` retrieves a previously imported
record. It performs no fitting and never substitutes another provider. It
requires the official final `short/000` window, exact horizon, original scale,
and the internal `official_reference` designation. This designation is not a
researcher-selectable preprocessing mode: the archived forecast was produced
from the original M4 training series and bypasses ShapeFM `standard`/`robust`
preprocessing and transformations.

## Stored contract and capability

`reference_forecasts` stores dataset and series identities, official M4 ID,
forecast/submission identity, rank and author, horizon, the `mean` vector,
point semantics, capability, source metadata, content hash, and creation time.
It stores no actuals, median, quantiles, or interval bounds.

`up_ff` and `low_ff` are deliberately not imported. Their M4 95% bounds do not
scientifically supply GIFT-Eval q0.1–q0.9 and are not used to fabricate q0.5 or
a median. Full probabilistic GIFT-Eval rejects `mean_only` inputs clearly.

Generated forecasts support `probabilistic` and `mean_only` capabilities. Mean
is always required. Median, quantile levels, and quantiles are all required for
`probabilistic` records and must all be absent for `mean_only` records.

## Common mean query

Researchers use one function without knowing the storage table:

```python
from util.experiment_execution import get_forecast_mean

auto = get_forecast_mean(
    database, dataset_id, "0", "auto_arima_forec", experiment_id,
    preprocessing_mode="robust", variant_id=variant_id,
)
smyl = get_forecast_mean(database, dataset_id, "0", "m4_smyl")
fforma = get_forecast_mean(database, dataset_id, "0", "m4_fforma")
```

Each call returns a numeric tuple of horizon length. Detailed Gate 4 retrieval
additionally exposes generated-versus-archived source, requested/executed
provider, submission metadata, package version, capability, and provenance.
If a live model has multiple matching transformations or experiments, callers
must provide enough identity—normally `experiment_id` and `variant_id`—rather
than receiving an arbitrary row. Omitting `preprocessing_mode` uses the stored
experiment default (`robust`); archived queries do not accept a preprocessing
mode.
