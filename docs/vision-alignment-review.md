# Research-vision alignment review

This review records the repository state after the POC2 object-adaptation and
period-resolution implementation. It is a planning record, not authorization to
change forecasting behaviour or remove scripts.
The findings below retain that historical scope; utility links now follow the
organisation map. See the workflow acceptance record for later implementation.

| Classification | Area and evidence | Impact | Future action |
|---|---|---|---|
| Outstanding approved requirement | The nine FFORMA-derived R methods are registered in [`forecast_methods.R`](../src/r/util/forecast_methods.R), but production configuration accepts only AutoARIMA and Chronos-2 in [`configuration.py`](../src/python/util/shared_configuration.py), Process 04 branches only to those providers in [`experiment_execution.py`](../src/python/util/shared_experiment_execution.py), and [`04_01_forecast_auto_arima.R`](../src/r/04_01_forecast_auto_arima.R) selects only AutoARIMA from the R pool. | Eight approved R methods are tested and callable but cannot yet be selected as production experiment models. | Integrate model configuration, task planning, generic R execution, persistence and common retrieval for all nine methods in a separately reviewed implementation. Preserve each method's requested/executed identity and fallback provenance. |
| Documentation discrepancy—closed | Architecture previously described only configuration v1 and could imply that generic frequency resolution meant general dataset support. [`architecture.md`](architecture.md) now documents v2, independent scoring seasonality, v1 compatibility and the current M4 Daily production restriction. | Prevents new period-1 results from being confused with historical period-7 results or unsupported datasets from being treated as production-ready. | Keep dataset capability statements separate from resolver capability as new importers and models are approved. |
| Future research capability—deferred | The vision calls for FFORMA features, alternative meta-learners, improved combination and distinct adjustment. Current combination remains the fixed two-model implementation in [`forecast_combination.py`](../src/python/util/p05_01_forecast_combination.py), and adjustment remains identity apart from recorded quantile rearrangement. | The repository does not yet implement the later ShapeFM decision research stages. This does not block the approved POC2 adapter work. | Retain these as deferred research phases. Do not describe them as implemented or change them without separate scientific approval. |
| Aligned foundation | DuckDB remains the persistent authority and Python remains the writer; R workers use JSON boundaries. The shared R input adapter is in [`time_series_input.R`](../src/r/util/time_series_input.R), and generated and archived means share [`get_forecast_mean()`](../src/python/util/shared_experiment_execution.py). | Preserves language boundaries, restartability, provenance and independent forecast retrieval. | Retain these contracts while expanding providers. |
| Possible removal candidate—decision required | [`04_03_forecast_m4_submission.py`](../src/python/04_03_forecast_m4_submission.py) is a thin JSON bridge around `retrieve_m4_submission()`. It is documented and tested, but no production repository caller was found; common mean retrieval overlaps part of its role. | Small duplicated interface surface. External callers may still depend on it. | Confirm external usage before deciding whether to retain or remove it. Do not delete it as part of this review. |
| Not a removal candidate | Numbered Process 01–06 wrappers are actively loaded by `PROCESS_WRAPPER_PATHS` in [`00_main.py`](../src/python/00_main.py). `LEGACY_WORKER_PATHS` in [`configuration.py`](../src/python/util/shared_configuration.py) preserves stored-database compatibility. [`get_m4_daily_series.R`](../src/r/qa/get_m4_daily_series.R) is the approved interactive QA workflow. | Removing any of these now would break orchestration, historical databases or requested QA. | Retain unless a later migration supplies replacements and explicit removal approval. |

The approved POC2 decision and implementation constraints are preserved in
[`poc2-object-adaptation.md`](poc2-object-adaptation.md) and
[`amp-poc2-object-adaptation-instructions.md`](amp-poc2-object-adaptation-instructions.md).
